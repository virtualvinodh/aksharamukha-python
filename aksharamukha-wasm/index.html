Aksharamukha, running entirely in your browser

No backend, no network calls after this page loads - the whole transliteration engine runs client-side via Pyodide (CPython compiled to WebAssembly). Everything under ./pyodide/ and ./wheel/ is vendored locally; nothing is fetched from a CDN. Script names and pre/post-option names below are queried live from the loaded package, not hardcoded.

Loading Pyodide runtime…

Two things don't work in this WASM build - found and verified while building it, not guessed:

  • Pre-option KhmerWordSplit - hard blocker. It needs python-crfsuite, a C extension with no WebAssembly build anywhere, WASM or not.
  • Tamil → IPA - calls a third-party pronunciation API that has no CORS headers, so no browser JS can reach it at all, Pyodide or not. Not fixable from this page.

Everything else - all ~180 scripts including Japanese (Hiragana/Katakana, via a vendored pykakasi), and every other option - runs correctly client-side.
